# Changelog

What changed in each AlphaCoreMP release, newest first. The downloads ride each release on its GitHub release page.

## 0.6.8 - 2026-11-11

- A test ship, "Smoke Wolf" (`wolf_smoke-wolf`), shipped in 0.6.7 by mistake. It is removed from the game data. A server folder drops the file at its first start after the update. Players: delete the old `mods\CC_Client` folder before copying the new one in, as the kit's README says; a new kit copied over the old folder leaves the test ship's file behind (the server no longer offers the ship).
- Hosts should update, unless custom ships are turned off (they are on by default): a notice the server sends about a rejected build could run past the chat length limit if the ships involved had long names, and that stopped the match for everyone. Every earlier release has this fault. The notice is now cut to the limit, and a fault while sending such a notice no longer stops the server.
- A custom ship now shows by the name typed for it in the ship editor in most places players and hosts used to read its id, such as `kept-wolf-ab92iu` or `cc-v3-wolf`; the join window and the ops GUI name kept ships only. The id is still the ship's key: commands and the join window still send it, the ship editor and the ops GUI show it when you point at the name, and a place that knows no name for a ship still shows its id.
- In the join window, the server's default ship reads by its name ("Server default: Wasp_test." instead of the ship's id), and so do the picked and current build rows, the build line and the ship line after Launch when they name a kept ship. A default that is one of the server's own ships keeps its id, as in the ship list.
- Picking one of your own builds with `/ship` now replies "next respawn: 'My Flash'" instead of its id. The pick-confirmed line, the other notices about a pick (unavailable, pending, rejected or expired) and the message when the server accepts or rejects a build you sent name the build too.
- The in-game `/builds` and `/share` lists show a build as its name and hull, such as "My Flash" (Wolf), without the id in front, and `/customs` shows names now too. Two rows with the same name and hull add the id in brackets, and picking a row still sends the id. A long name is cut first, so marks such as (shared) or (piloting) stay visible. Saving a build reads "saved as local build 'My Flash'", or "saved as a second copy of 'My Flash'", instead of a numbered id, and the other save and fly-next replies name the build too. An apostrophe in another player's build name shows as ` in these replies, so the name cannot close the reply's quotes.
- A kept ship spawned with `/spawnfoe` or `/spawnfriend` carries its name in the battle and in the `/transfer` list, and the reply reads "spawned 1x My Wolf (wolf)" instead of the ship's id; the queue-full replies name it the same way.
- In the ship editor, the lines about flying, loading and the server's answer, and the next-ship line at the bottom, name the build instead of its id. On the host's ship card, a named kept build no longer shows its id under the name, the removed builds show their names (the first 24 characters) and hulls, and a kept or removed build with the same name and hull as one above it reads "(older copy)".
- Promote in the ship editor now goes by the ship's name. A ship loaded from the server's list and changed replaces the original only while it keeps the original's name. Under a new name, Promote adds it as a new ship and leaves the original as it was (in 0.6.7 any changed loaded ship took its original off `/ship`, whatever it was named); if a kept ship on that hull already has the new name, that one is replaced. A build not loaded from a ship replaces the newest kept build with its name on its hull (the editor reads "replacing your kept '<name>'…") instead of adding a second one. Upper or lower case and spaces around the name do not matter, and a blank Name always adds. A replaced ship waits under Taken off (a ship the server comes with) or Removed builds (a kept build), where Put back restores it.
- In the ops GUI, the seat table and the Customs menu's detail line show kept ships by name, and "Exported, not kept yet" names the removed kept ships; in "Kept for everyone", the id that sat beside a ship's name moved into its tooltip. The exported copies list newest first: a copy whose name a kept ship or a newer copy already shows reads "(older copy)", and a kept ship's own leftover file reads "(already kept)". The Forget and Keep confirmations name the ship, such as Forget "My Wolf" (wolf)?, and still act on its id. Keep on a removed ship that another kept ship replaced now asks "Put back" and says which ship leaves the `/ship` list ("the copy in its place" when both carry the same name).
- When the server has more ships than the join window's list holds (28 rows), the rows are now shared between the ships the server comes with and the host's kept ships, so the newest kept ships stay on it (before, a host's sixth kept ship could be missing). The join window also always learns which ship is the server default. A ship left off the list can still be typed by its id.
- The list of removed ships that Put back works from now keeps the 32 most recently removed; it used to keep the first 32 by name, so a ship just replaced could be missing from it. If a host replaces the kept ship that is the server's default for joiners, the default now moves to the new build and comes back with a Put back. The move lasts until the server stops: the saved default setting is not changed, so set the default again before the next start (a default that names a removed ship is refused at the start, and joiners then fly the match's own ship). Remove or Forget kept of a kept ship that is the default is refused with a reason.
- `/shiplist` now also sends the removed ships' names, in an encoded line that the 0.6.8 kit reads for the ship editor instead of printing it in chat. When you type `/shiplist` yourself, a line the kit cannot read shows as its encoded text.
- When the join window gets no reply, its messages now also name an older server as a possible cause: "Ship list: no reply from <address>:<port> (server not up yet, wrong address/port, or a server older than this kit)", and Launch adds "(a server older than this kit also gives no answer)". Its "This CC_Client folder is not the host's kit (a file differs)" message now says to delete the `CC_Client` folder and copy in the one from the host's kit zip.
- The joiner kit and the server must be updated together: a 0.6.7 kit cannot join a 0.6.8 server, and a 0.6.8 kit cannot join a 0.6.7 server.

## 0.6.7 - 2026-11-10

- A custom ship the host has kept for everyone now shows by the name it was given in the ship editor (up to its first 24 characters) instead of its id: in the join window's ship list, in the in-game ship and spawn lists, and in the ops GUI's "Kept for everyone" list, where the id stays visible after the name. Two kept ships with the same hull and name each add their id in brackets. Elsewhere, such as the reply to `/spawnfoe`, the id still shows.
- Kept ships can now be fielded with the admin commands `/spawnfoe` and `/spawnfriend`: they lead the list those commands show, `/spawnfoe <text>` finds them by part of their name or hull as well as their id, and the in-game list filters by ship and hull name too. Picking one still takes its exact id, and adding `officer` gives a kept ship an officer too.
- An admin who joins before the round starts no longer gets the server's whole ship list printed into chat. The server also does more of its one-time loading when it starts: less is left for the first join (which can still take a few seconds), and the first map mark, the first ship spawned by command and the first heat-seeking or proximity-fuse missile no longer hitch the match for a moment.
- Fuse bombs, such as the proximity bombs Wasp fighters drop, now end in the game's own blast on each player's game, whether the fuse trips near a target or the bomb runs out of flight time. A blast that hits a ship that is not a fighter (other ships and your own alike), or a bomb that strikes another ship directly, is now applied on your game through the game's own damage path, and the server's hull, armor and flux values are put back at once, so the server still decides the damage. Whether a damage number appears is the game's own rule: damage numbers must be on, and the ship hit must be yours, your target or the one the camera follows, or the bomb must come from your ship or its fighters, or that ship must already show a floating number or message.
- A missile or bomb hit on your own raised shield near full flux is now better guarded against a false overload. Your game replays hits the server confirms on your ship, and near full flux a replay could overload the ship on your game alone and drop its shield, which could then lower it on the server too. The replay's flux estimate now includes the attacker's size and your ship's shield damage modifiers, and a hit whose flux would not fit under the flux capacity is not replayed (a real overload still comes from the server); replayed hits on other ships get the same ceiling.
- When a different player takes over a seat, the previous player's name is now dropped from that ship's name tag and from server replies such as the `/transfer` list, which now also updates as soon as a seat's name changes. The same happens when a player comes back to their seat without a name.
- In the ship editor, a Shift + drag paint now carries on across the fighter wing slots and the Groups table's rows as the mouse moves; before, it stopped after the first one. Asking the editor for a hull's stats with all skills while the game is still starting now gets the reply "the game has not finished starting yet" instead of an internal error; a request after start works.
- The client mod bounds more of what a server feeds it. The weapon-mount records it keeps from full ship snapshots are capped at 262,144 in total (about 14 MB); past the cap the newest snapshot is refused and counted. A bomb-hit report is refused when it names a fighter, a missile that is not a fuse bomb, or a blast too far from the ship it names, or when it would make your own ship the source of a bomb your seat did not fire, and at most 32 are applied per server tick. A normal match comes nowhere near these caps.
- The joiner kit must be updated to 0.6.7, together with the host's server. A kit from 0.6.6 or earlier is refused at a 0.6.7 server: its join window reads "Ship list: This kit is outdated - get the NEWEST kit zip from the host." A 0.6.7 kit at a server still on 0.6.6 or earlier gets no reply at all, even though that server is running: the join window reads "Ship list: no reply from <address>:<port> (server not up yet, or wrong address/port) - you can still type a ship id." and Launch reads "Match not ready: No answer from the server yet - press Refresh; if it repeats, check the address and port with the host." That server is older than the kit: the host updates it to 0.6.7, or the player joins with the kit from that server.

## 0.6.6 - 2026-11-09

- Optional mods are now checked at the door. The game puts every mod it runs into its content check, and the server accepts its required mods plus any combination of the optional mods it published, each with the same version and files. Before, the game left optional mods out of that check, so a joiner could pass off a mod the host never published as optional. A host can publish at most 8 optional mods (the server keeps one fingerprint for each combination): a list of more than 8 is refused in the ops GUI's Mods tab, at Start and when the server starts, while a list already over 8 can still be lowered in the Mods tab. The in-game refusal message now reads "CONTENT MISMATCH - your kit or mods differ from the server's: close the game, run join-cc again and press Launch (it re-reads the server's mod list and says what to fix)".
- The join window now checks which Starsector it sits in before Launch. If the game's version is not exactly the one the kit is for, Launch is refused under "Wrong game version": "This kit is for Starsector 0.98a-RC8, but the Starsector it is installed in is <version>. Install Starsector 0.98a-RC8 and move this kit into that game's mods folder, or get the host's current kit if their server was updated." If the game's version cannot be read, Launch goes on as before.
- The client mod now bounds the rest of what a server feeds it, so a misbehaving server can no longer grow the client's memory: the lists of ship and missile ids and queued events are capped (most at 65,536 entries), each buffer of incoming snapshot data at most 16 MiB, and an event held waiting for data that never arrives is dropped after 20 seconds. Past a cap, data is dropped and counted, and the first drop is written to the client's log. The ship builds a server sends, which the client saves on disk for the ship editor, are now pruned to the newest ones, an identical build is not written again, and that cache uses at most a tenth of the file-write allowance the game gives all mods each time it runs. A normal match should come nowhere near these caps.
- Observers now get one number when they join, and "observer N" means the same observer in `/ban`, `/mute` and `/chatmute` and in every player's list. Before, each list counted observers on its own, so one number could name different people. Numbers follow join order and can skip, and none is reused while the server runs; `/mute` also lists an admin observer under its own number. Hosts: the server log's line for an admitted observer now ends with `observer_ordinal=N`.
- Hosts: each start of the server package now removes its oldest flight folders from `run`, keeping the newest 20, and says how many it removed. To keep another number, set `run.keepFlights` in `launcher.properties` (2 to 10000, or 0 to keep them all); any other value refuses the start. On Windows a folder a game window still has open is only partly removed and is tried again at the next start; copy a flight folder elsewhere to keep it for good.
- Hosts: with "Launch debug WATCH" and a "Second game folder" set, the two join windows no longer share one settings file (a window could start with the address the other window's press had just written); each window now keeps its own saved entries (name, ship pick). The first time after this update, the second window opens with an empty name and the default ship.
- The joiner kit must be updated to 0.6.6: an older kit is refused at the door, and so is a 0.6.6 kit at a server still on 0.6.5. A 0.6.1 to 0.6.5 kit's join window reads "This CC_Client folder is not the host's kit (a file differs) - extract the host's kit zip again, then press Refresh."; an even older kit is refused as outdated.

## 0.6.5 - 2026-11-09

- Hosts: an update can now go back to an older server version on purpose. `update.bat <that zip> --allow-older` (Linux: `sh update.sh <that zip> --allow-older`) prints a "going back: <old> -> <new>: N files to replace, ..." preview and applies the zip; without the flag an older zip is still refused, and the refusal now names the flag. Players then need that version's kit from its `kits` folder (the next start names it), and the older version lacks every fix made after it, so update forward again as soon as a version with the fix is out. The updater now refuses any second argument other than `--allow-older`. See the README, "Why an update was refused".
- The client mod bounds the ship-removal events it accepts from a server: a round takes at most 65,536 such events about other ships (your own ship's event is never dropped), so a misbehaving server can no longer grow the client's memory for the whole round. Past the cap, the first dropped event is written once to the client's log and the rest are counted; the per-event log rows are capped as well. A normal round should come nowhere near the cap. A leftover entry is also cleared now for a ship that was destroyed before the client ever saw it.
- The server's simulation thread does less work per tick: the frame sent to players is built from one snapshot per capture instead of several, roster and position lookups are cached, and each ship's weapons are read once per step. Play is unchanged; a test round on a build with these changes ran as smoothly as the same round on 0.6.4.
- Hosts: a server started with the `record=diag` or `record=full` setting now also runs with the JVM flag `-XX:+DebugNonSafepoints`, so the profile it records attributes time more precisely. Nothing else about recording changes.
- The joiner kit must be updated to 0.6.5: the version number is part of the kit's content check, so an older kit is refused at the door.

## 0.6.4 - 2026-11-07

- Hosts: a player's text chat can now be muted. On "Players", pick the seat and press "Mute chat" under "Seat actions" ("Unmute chat" lifts it). In the game's chat an admin types `/chatmute` for a numbered list, then `/chatmute #<n>` (or `/chatmute <name>`); `/chatunmute` lists the mutes and `/chatunmute #<n>` lifts one. A muted player keeps playing and their commands still work; nobody sees their lines; the mute follows them across re-joins and lasts until it is lifted or the server stops. Command-file twins: `chat-mute <seat>` and `chat-unmute <seat>`. See the README, "Kicking, muting and banning players".
- `/mute` (voice, for yourself only) now answers "muted seat N's voice for you (Name)" so it is not mistaken for the text mute, and `/unmute` points to the right verb instead of toggling the voice mute.
- The server does less work per tick on its simulation thread: the frame send to players runs on its own worker, and several per-tick reads of the game's objects were trimmed. Play is unchanged.
- The joiner kit must be updated to 0.6.4: the version number is part of the kit's content check, so an older kit is refused at the door. No other change to the client mod.

## 0.6.1 - 2026-11-05

- Fixed a crash with the Arma Armatura mod on the server: when a player picked the Valkazard Kai or the Raiden EX, every player's game crashed once its blade drones launched (0.4.0 to 0.6.0). Fighters launched from another player's or an AI carrier now carry a fighter wing on your screen, as the game expects, and a wing that refills after losing every fighter follows a live fighter on the radar.
- A spawned AI ship of a mod that randomizes its weapons at spawn (Arma Armatura's Aleste) now carries the same weapons on every player's screen; before, each game rolled its own.
- Retreating with a healthy ship (the bottom edge's Enter prompt, or a retreat order from the tab map) no longer strands you as a shuttle with no respawn while the other players see your ship bouncing at the map edge: the server now reads a healthy departure as a departure, not a kill, and you fly back in. `/despawn`, the end of a transfer pod and a phase dive now vanish the ship on the other screens rather than kill it.
- With the chat box open, Enter sends the line and does nothing else, so typing a command can no longer retreat your ship. With chat closed at the bottom edge, Enter still opens chat and retreats, as the game's prompt says.
- A kill that leaves no wreck on the server (a ship blown apart by one heavy volley) now leaves no wreck on the players' screens either. Tested in rows only; not yet seen in a match.
- Linux hosts: "Player game folder" is required for "Join from this PC" and "Launch debug WATCH". A blank row is now refused by name (0.6.0 judged the Windows game files in "Game folder" instead and asked for a kit under a folder that could never start the game), and the Setup tab's hint states the rule for each platform. A set folder that holds no game is named, without the "clear it" advice that could only fail on Linux.
- The joiner kit must be updated to 0.6.1: the connection format changed, and a 0.4.0 to 0.6.0 kit is refused at the door with "kit outdated".
- The hosting README's ops GUI section adds a caution for hosts who reach the ops GUI through an ssh tunnel: keep the host's OpenSSH current (an older OpenSSH on musl-based Linux accepts over-long passwords on accounts that should take none).

## 0.6.0 - 2026-11-04

- New "Player game folder" (Setup tab, beside "Game folder"): on a Linux host, the Linux install of the game that "Join from this PC" and "Launch debug WATCH" start your own windows from, while the server keeps running the Windows game files in "Game folder". Blank means "Game folder". A folder set there that holds no game refuses the press and names the row. Without it, those two buttons could not work on a Linux host, though 0.5.0 said "Join from this PC" did.
- "Launch debug WATCH" works on a Linux host too, with a "Player game folder" set (proven in WSL only; the second window joins on this computer there, since the VPN route is Windows only).
- The ops GUI's Mods tab "Needs" column reads a mod's `mod_info.json` the way the game does, so a `#` comment no longer hides a dependency, and it names a pulled-in library whose own requirement is missing.
- A player's game that closes while the server is still talking to it now finishes its last messages before it says goodbye. 0.5.0 said this of a player's game; it was true of the test client only. The player's game does it since 0.6.0.
- Voice chat on Linux uses Java's own sound line, where ALSA routes to PipeWire or PulseAudio. The 0.5.0 note's "about 74 ms more delay" was not measured on Linux; the delay to the speaker there is unmeasured.

## 0.5.0 - 2026-11-04

- The kit runs on Linux: copy `CC_Client` into `mods/` of a Linux Starsector 0.98a-RC8 and run `bash mods/CC_Client/join-cc.sh` from that folder. The game runs on its own Java (`jre_linux`); the kit's bundled Java stays Windows-only. The kit README's "On Linux" section lists the differences and the sound and `xrandr` packages a distribution may lack.
- The Linux game is a different build of the same version, so the kit's compatibility agent translates the mod's engine references as the game loads. No game file is copied or changed.
- A Linux host's ops GUI has "Join from this PC" too: start `ops-web.sh` from a terminal inside your desktop session. "Launch debug WATCH" stays Windows-only.
- Voice chat on Linux uses Java's own sound line: it works where ALSA routes to PipeWire or PulseAudio (the usual desktop), with about 74 ms more delay to the speaker than on Windows.
- A player's game that closes while the server is still talking to it now finishes its last messages before it says goodbye.
- The ops GUI's Mods tab has a "Needs" column: which mods a mod needs, which mods need it, and when an unticked mod loads anyway because a required mod needs it (or an optional one would refuse the start).

## 0.4.0 - 2026-11-03

- The 0.4.0 kit is required. A 0.3.0 or older kit is told at the door that it is outdated.
- Other players' screens follow each pilot ("Setup", "Advanced"; `pilotship.replicas`, on as shipped): a player whose game runs on the kit's own Java runs a pilot's ship hullmods, ship system and weapon scripts from that pilot's held keys, so cables, smoke, debris and jets show on their screen as the pilot fires them. Other starts see them through the server's corrections.
- MagicLib abilities of other pilots fire on your screen too, on the kit's own Java start: the kit's agent changes MagicLib's ability class in memory as it loads. The host can turn the server half off.
- Mod ships are pickable: ships kept in a mod's variant subfolders (boss ones included) are on the pick list. Hide the ones you do not want on the ops GUI's "Players" tab; the hide list now holds every shipped ship.
- LunaLib settings: the server's values come from `luna-settings\<modId>.json.data` (the "Mods" tab names the file) and are kept across server updates. The host README's LunaLib section has the three things to know.
- Keys stay in the game: keys typed while the game window is not active, or while a game dialog is open, never leave your game.
- A mod ship's loadout no longer swaps on respawn, and the Aleste's travel drive fires on the server.
- The ops GUI: an "on" box per mod on the "Mods" tab, a narrow layout that fits one seat card, and a named message when Windows has reserved the chosen port.
- Linux hosts: a `stop.sh` followed within a second by `serve.sh` no longer stops the new server at boot.

## 0.3.0 - 2026-10-30

- Every player needs the 0.3.0 kit. An older kit is refused when it joins and the join window says the kit is outdated.
- Mod hotkey abilities follow the pilot without MagicLib: players' held keys and mouse buttons reach the server, and the pilot's ship reads them in its own scripts (hullmods, ship system, weapon every-frame scripts), whatever keys the player bound. Not covered: the mouse pointer, one-by-one keyboard events, and battle-wide combat plugins. Details in the host README's Mods section.
- "Each pilot's ship counts as the player's" now ships on (it was off in 0.2.0); it is what lets those abilities follow the pilot. The host can turn it off in the ops GUI before Start ("Setup", "Before start", "Advanced").
- Known limit: a game control rebound during a match keeps its old key on the server for mod abilities until the next match starts. Set your keys before the match.
- Host: the ops GUI's "Players" table now sizes to its seats; with three or more players it showed two rows and a scrollbar.
- Host, Windows: with a "Second game folder" set, "Launch debug WATCH" joins its second window through the VPN's public address, as a remote player would, when the server is bound to the VPN address; the first window joins on this computer.

## 0.2.0 - 2026-10-30

- Every player needs the 0.2.0 kit. A 0.1.x kit is refused when it joins and the join window says the kit is outdated.
- Ships from the mods the server runs can be picked in the join window and flown.
- MagicLib abilities follow the pilot: an ability from a MagicLib-based mod, pressed on its own hotkey, now fires on the server for the ship that player flies instead of running there by the mod's AI. On as shipped; the host can turn it off in the ops GUI before Start ("Setup", "Before start", "Advanced": "MagicLib abilities follow the pilot").
- New host switch "Each pilot's ship counts as the player's" (off as shipped, same place): the server treats each player's ship as the player's ship inside that ship's own hullmods, ship system and weapon scripts, so an effect a mod or the game gives only to the player's ship works on the server as it does on that player's screen. Not for hit effects, battle-wide scripts, or scripts that read the keyboard or mouse or draw.
- Mod authors: the pilot contract in the source README tells a mod, from two custom-data keys on a ship, whether a player flies it and which ability slots the pilot holds. It needs no AlphaCoreMP code to compile or run.
- The host README has a Mods section: which mods work as they are, which need care, and what LazyLib, LunaLib and MagicLib do on the server (LunaLib's version checker contacts GitHub from the server computer at every start).

## 0.1.2 - 2026-10-28

- Mods that bring their own `settings.json` now load on the server the way they do in the game: a mod's rule-command packages and plugins are read after the mod list is set, so library mods such as LazyLib and MagicLib start on a server that requires them instead of stopping it at the rules load. Mod combat code that reads the keyboard sees no keys held on the server instead of crashing it.
- After an in-place update, the report says that players need the new kit only when the kit's content actually changed; an update that touches only match settings prints no such line.
- Both READMEs open with a short summary that says what to attach when reporting an issue (hosts: the server's run log; players: the session report), and the host README has a Mods section.
- The public repository carries a CHANGELOG with one section per release.

## 0.1.1 - 2026-10-27

- The joiner kit now carries every custom ship variant the mod ships, not only the ones the built-in match shapes use. The kit has to match the host's server: a 0.1.1 host needs the 0.1.1 kit, and an older kit is turned away.
- Building from source works on Linux too: the one `build.ps1` runs under PowerShell 7 on Windows and on Linux. The server builds against either game download; the client mod needs the Windows game files, as the source README explains.
- Hosts update in place: stop the server, close the ops GUI, drop the new zip onto `update.bat` (Linux: `sh update.sh <zip>`) and start again. Settings, passwords, bans, kept ships and recordings are kept. Players replace their `CC_Client` folder with the one from the new kit.

## 0.1.0 - 2026-10-27

AlphaCoreMP 0.1.0 - the first public release.
